# AIE4 — Предобработка документов для RAG

## 1. Описание проекта

Проект посвящён предобработке текстовых документов для систем Retrieval-Augmented Generation (RAG).

Основные этапы:
1. Очистка и нормализация текста.
2. Токенизация и разбиение текста на чанки.
3. Сравнение стратегий разбиения.

## 2. Структура проекта

- `text_cleaner.py` — функции очистки текста.
- `test_text_cleaner.py` — тесты очистки текста.
- `create_cleaned_documents.py` — создание очищенного текста.
- `data/cleaned_documents.txt` — очищенный текст документов.
- `chunking.py` — токенизация и разбиение на чанки.
- `test_chunking.py` — тесты чанкинга.
- `data/chunks.json` — чанки, созданные с помощью разбиения по словам.
- `compare_strategies.py` — сравнение двух стратегий.
- `results/strategy_A.json` — результаты разбиения по предложениям.
- `results/strategy_B.json` — результаты разбиения по словам.

## 3. Требования

- Python 3.10 или новее.
- pytest для запуска тестов.

Внешние библиотеки для токенизации не используются: обработка реализована средствами стандартной библиотеки Python.

## 4. Запуск проекта

Все команды выполняются из корневой папки проекта.

### Создание очищенного текста

```powershell
python src/create_cleaned_documents.py
```

### Запуск тестов

```powershell
python -m pytest src -v
```

### Создание чанков

```powershell
python -c "import sys, json; from pathlib import Path; sys.path.insert(0, 'src'); from chunking import chunk_document; text=Path('src/data/cleaned_documents.txt').read_text(encoding='utf-8'); chunks=chunk_document(text, chunk_size=100, overlap=10, strategy='words'); Path('src/data/chunks.json').write_text(json.dumps(chunks, ensure_ascii=False, indent=2), encoding='utf-8'); print(f'Создано чанков: {len(chunks)}')"
```

### Сравнение стратегий

```powershell
python src/compare_strategies.py
```

Результаты сохраняются в папке `src/results/`.

## 5. Очистка и нормализация

Функция `clean_text()` объединяет несколько этапов:
- нормализацию пробелов;
- удаление специальных символов;
- повторную нормализацию пробелов;
- нормализацию регистра.

Параметр `keep_punctuation` управляет сохранением разрешённых знаков препинания. Параметр `lower` определяет, переводить ли текст в нижний регистр.

Сохранение пунктуации помогает не терять структуру предложений. Приведение к нижнему регистру уменьшает различия между словами, которые отличаются только заглавными и строчными буквами.

## 6. Токенизация и чанкинг

Используются две функции токенизации:
- `tokenize_by_sentences()` — разбиение по границам предложений;
- `tokenize_by_words()` — разбиение по пробельным символам.

Функция `chunk_fixed_size()` формирует чанки заданного размера с возможным перекрытием.

Для файла `data/chunks.json` используются параметры:
- размер чанка — 100 слов;
- перекрытие — 10 слов.

Перекрытие сохраняет часть контекста между соседними чанками и помогает уменьшить потерю информации на границах.

## 7. Сравнение стратегий

**Strategy A — по предложениям**
- размер чанка: 5 предложений;
- перекрытие: 1 предложение.

Преимущество — лучше сохраняются смысловые границы. Недостаток — фактический размер чанка в словах может меняться.

**Strategy B — по словам**
- размер чанка: 100 слов;
- перекрытие: 10 слов.

Преимущество — предсказуемый размер фрагментов. Недостаток — граница чанка может проходить внутри предложения.

### Полученные результаты

| Метрика | Strategy A: предложения | Strategy B: слова |
|---|---:|---:|
| Количество чанков | 11 | 6 |
| Среднее слов в чанке | 59,00 | 99,33 |
| Минимум слов в чанке | 39 | 96 |
| Максимум слов в чанке | 74 | 100 |
| Внутренние границы без конечной пунктуации предложения | 0 | 5 |
| Доля таких границ | 0% | 100% |

Strategy A использует чанки по 5 предложений с перекрытием в 1 предложение. Strategy B использует чанки по 100 слов с перекрытием в 10 слов.

Strategy A сохраняет границы предложений, поэтому лучше поддерживает целостность текста. Её чанки имеют разный размер в словах. Strategy B обеспечивает более предсказуемый размер, но границы чанков могут проходить внутри предложений.

Дополнительная метрика — доля внутренних границ чанков, которые не заканчиваются на `.`, `!` или `?`. В текущем наборе она составляет 0% для Strategy A и 100% для Strategy B. Это приближённая структурная метрика, а не прямое измерение качества поиска. Она может ошибаться на сокращениях, сложной пунктуации и других особенностях текста.

Для оценки реальной эффективности в RAG потребуются тестовые запросы, эталонные релевантные документы и метрики поиска, например Recall@k. Поэтому по результатам текущего эксперимента нельзя сделать вывод, что одна стратегия всегда обеспечивает лучший поиск.

### Вывод и компромиссы

Разбиение по предложениям лучше сохраняет смысловые границы, но может создавать чанки разной длины. Разбиение по словам даёт более равномерные фрагменты, однако может разрывать предложения. Перекрытие помогает сохранять контекст между соседними чанками, но увеличивает объём повторяющегося текста и размер индекса.

Оптимальный вариант зависит от структуры документов, типа пользовательских запросов, размера чанка, перекрытия и настроек поиска. Для выбора стратегии в рабочей RAG-системе необходимо сравнить качество извлечения на отдельном наборе тестовых запросов.
